# Codex 用量采集器 · Windows v1.2.1

这是可以独立运行的 Windows 小程序。双击 CodexUsageCollector.exe，不需要另外安装 Python，也不需要让 AI 执行命令。

## 开始使用

1. 解压压缩包，双击 CodexUsageCollector.exe。普通 Windows 用户即可运行，不需要管理员权限。
2. 该电脑需要已经用 ChatGPT 账号登录 Codex。程序默认读取 CODEX_HOME，未设置时读取 %USERPROFILE%\.codex；也可点击“选择目录”，选择含 auth.json 的目录。
3. 给“网页账号名称”填写一个固定名称，例如 personal、work、backup。不同实际账号使用不同名称；同一账号再次运行保持名称不变。
4. 服务地址按要求默认留空。现在可以直接点击“仅采集”，查看真实额度并存入待上传队列；准备上传时，填写你的网页根地址，例如 https://quota.example.com 或 https://example.com/quota。
5. 上传密钥填写现有访问凭据.env 中的 UPLOAD_TOKEN。不是 READ_TOKEN，也不是 OpenAI API Key。
6. 点击“采集并上传”。查看下方记录：实时额度与用量分析分别报告结果。部分失败时，已成功的部分会保留。

## 按钮

- 采集并上传：获取当前真实额度和所选分析，先加入本机队列，再补传当前账号和地址的待上传数据。
- 仅采集：只读取数据并保存在本机；不需要网址和上传密钥。
- 立即上传：补传当前账号 / 地址的待上传队列，不重新查询。保留原采样时间与 report_id，服务器会去重。其他账号或地址的数据仍保留在各自队列中。
- 导出 JSON：选择目录，导出 usage-时间.json 与 analytics-时间.json；每个文件都可以单独粘贴到网页“接入 / 上传”。
- 保存设置：保存账号名称、网址、登录目录、分析选项，读取 / 上传间隔，以及勾选后加密保存的上传密钥。
- 打开网页：打开你填写的服务地址。

默认包含近 30 天分析和本机最近活跃的最多 100 个根聊天。取消勾选“包含 30 天分析与聊天排行”后，只读取并上传实时额度。

## 自动读取与自动上传

界面“自动运行”区域提供两个独立间隔，默认每 5 分钟读取、每 10 分钟上传。单位为分钟，可填 0–1440 的整数。**0 表示关闭对应的自动功能**，即使前面的复选框仍勾选也不会执行；取消复选框也可关闭。两项都为 0 时不会启动定时器，手动采集和上传仍可使用。

1. 填好账号和登录目录。需要自动上传时，再填写服务地址与 UPLOAD_TOKEN。
2. 设置两个间隔，点击“开始自动”。已启用的读取首次立即执行；已启用的自动上传首次在一个上传间隔后执行。
3. 每项从上次操作结束开始计算下次间隔。界面显示下次执行时间、执行中状态和待上传数量。
4. 点击“停止自动”停止后续任务；如果已有网络请求在执行，会完成当前操作。停止后即可修改设置，再点击开始。

仅自动读取时，把上传间隔设为 0，地址和密钥可以保持为空。仅自动上传时，把读取间隔设为 0，会发送已有队列，不启动新的读取。队列为空时不会反复发送空请求。

采集 / 上传使用同一工作线程，不会重复并发执行。遇到耗时请求，会在它结束后执行已经到期的另一项。电脑睡眠、断网或长时间阻塞后，不会连续补跑所有错过的采集次数；恢复时执行一次，再按配置间隔继续。无法补回没有实际采样期间的额度变化。

默认开启托盘常驻：最小化或关闭窗口后继续运行，点击托盘图标可恢复界面；要真正退出，请使用主菜单或托盘右键菜单的“退出程序”。关闭托盘常驻后，关闭窗口才会退出。重新打开后会恢复间隔和待上传队列，但需要再点击“开始自动”，不会自行开始联网。没有创建 Windows 系统定时任务、开机启动项或系统服务。

## 托盘、通知与上次重置

鼠标停在托盘图标上会显示本机已采集账号的剩余额度，例如 `14%/weekly · 62%/5h`，下面标明账号和采样时间。weekly 优先显示；未返回的窗口不显示为 0%。每次读取后更新，重开程序先显示上次采样；仅移动鼠标不会额外联网或调用 AI。

窗口顶部的“设置”菜单提供两个独立开关，修改立即生效并保存：

- 托盘常驻：默认开启。最小化 / 关闭窗口隐藏到通知区域，读取和上传按现有间隔继续。托盘图标可能收在任务栏的“显示隐藏的图标”中。点击图标恢复窗口；右键可打开、隐藏、开始 / 停止自动或退出程序。关闭常驻后，关闭窗口即退出。
- 额度归零 / 重置通知：默认开启。**归零指剩余额度为 0%（已用 100%）**；持续为 0 不重复提醒，额度恢复后再次耗尽才重新提醒。首次采集已耗尽也会提醒一次。已记录的通知不会因重开或重传重复弹出。

开启常驻时使用 Windows 通知；关闭常驻时使用不阻塞采集的 App 弹窗。系统通知遵循 Windows 通知与勿扰设置。关闭通知只停止弹窗，仍保存重置历史。

App 直接比较本机相邻采样，不依赖网页或上传成功。每个窗口分别显示“上次重置”的检测时间，以及 **5h / weekly + 计划内重置 / 疑似突发重置 / 计划周期切换**。采样不足、缺少有效原计划时间或跨越太久时，只通知“类型待确认”，不会假装已经确认重置；没有观测到过的重置显示“尚未检测到”。

本地检测与网页使用相同规则：明显已用额度下降阈值为 2 个百分点、计划时间容差为 5 分钟。计划时间切到下一周期而未观测到额度下降，单独标为“计划周期切换”。突发重置和平台额度调整仅凭采样无法完全区分。

**检测时间不等于精确发生时间。** 网页同时显示原计划时间或两次采样组成的发生区间；App 显示首次发现变化的采样时间（本机时区）。网页统一使用香港时区。最近重置记录不随网页 1 / 7 / 30 / 90 天筛选消失。

上传后 App 会同步该账号的网页重置历史，并与本机记录取最新值；同步历史不触发旧通知。更新前只保留在网页的记录，可通过一次“立即上传”同步（即使本机队列为空也可以）。网址未配置或服务暂不可用时，继续显示本机记录。

常驻不会自行开启定时器，仍需点“开始自动”；间隔为 0 仍代表关闭对应功能。程序退出、电脑关机或休眠期间无法采样或通知；没有安装开机启动项或系统服务。

## 待上传队列

每次读取的额度与分析分别作为一条记录写入 SQLite 队列，因此一次完整读取通常新增 2 条待上传记录。服务器确认 accepted、duplicate 或旧采样状态后才移出队列；失败、断网或程序退出不会删除未确认的数据。重启后仍可补传。

同一类型的数据按原采样时间从早到晚提交；较早记录失败时，保留它和后续同类记录，避免后上传的新额度覆盖尚未比较的旧额度。额度和分析的失败分别处理。大量积压数据会分轮上传，每轮限制工作量，界面会显示剩余数量。

队列按账号和目标地址隔离。地址为空时采集的记录，会在第一次上传时绑定到你填写的服务地址。已经绑定旧地址的数据不会因修改地址就被自动发送到新地址；切回原账号 / 地址可以继续补传。界面会提示其他账号 / 地址还留有多少记录。

最多保留 10,000 条、约 256 MiB 待上传内容；接近上限会提示先上传并暂停新增采集，不静默删除旧记录。旧版本最近一次采集会仅迁入队列一次；如服务器已经收到过，补传会被去重。

## 数据与账号

5 小时 / 每周按实际窗口时长识别，不按接口的主副顺序猜测。数据源未返回的窗口显示“未返回”，不会写为 0。预计重置时间使用接口返回时间，不通过倒计时假定发生重置。

首次采集会在本机记录账号名称和当前登录的匿名指纹。若以后切换了 Codex 登录却继续使用同一个网页账号名称，会提示改用对应名称，防止混合历史。同一网页账号最好由一个采集端负责分析上传，避免不同电脑的本地聊天列表相互替换。

此程序只查询统计，不调用模型、不购买或兑换额度，不上传聊天正文。OpenAI 登录凭证仅发送给固定的 https://chatgpt.com 官方统计接口；上传到自建网页的是额度、统计明细、聊天 ID 和标题等元数据。

## 本机保存

默认目录：%LOCALAPPDATA%\CodexUsageCollector

- settings.json：设置。上传密钥通过 Windows DPAPI 加密，通常只能由保存它的 Windows 用户在这台电脑解密。
- last_collection.json：最近一次采集的界面预览与导出缓存，包括聊天标题；不包含 OpenAI 登录凭证或上传密钥。下一次采集会覆盖它。
- usage_monitor.sqlite3：按账号 / 登录身份隔离的采样基线、归零去重状态、重置记录及网页历史缓存。
- pending.sqlite3：持久待上传队列。程序运行时可能伴随 -wal / -shm 文件；关闭程序后复制整个数据目录可迁移统计记录。Windows 加密密钥仍需在新电脑重新填写。

把 EXE 复制到其他电脑后，需要在那里填写设置和密钥；不要把本机的数据目录作为发给其他人的通用安装配置。更新时先关闭旧版本，替换 EXE 即可，%LOCALAPPDATA% 中已有配置会保留。

## 常见情况

- 未找到 auth.json：检查登录目录。此版本支持 auth.json 中的 ChatGPT 登录状态，不能直接读取仅保存在其他凭证库中的登录信息。
- OpenAI 返回 HTTP 401：先在 Codex 中恢复有效登录，再重试。本程序不修改或自动刷新 Codex 登录文件。
- 上传返回 HTTP 401：检查是否用了 UPLOAD_TOKEN。
- 服务连通检查失败：检查最终网址、Nginx 的路径转发和网络。支持 HTTP 与 HTTPS，支持网页子路径；不接受携带用户名密码、查询参数或片段的网址。
- 分析部分失败：可以先取消分析勾选，上传实时额度。详细原因会显示在运行记录中。
- 旧采样：服务器已收到较新的数据；重试不会覆盖较新状态。
- 当前来源接口与本地任务索引格式基于 Codex Desktop 26.915.4065.0 验证，后续 Codex 更新可能需要适配。

此 EXE 是本次构建的未签名程序；企业的应用控制策略可能限制运行。源码包含在 source 目录，可以审阅或自行构建。

## 无窗口采集（可选）

程序也提供只采集的命令行模式，不上传、不调用模型：

```powershell
.\CodexUsageCollector.exe --collect-only --account my-codex --output .\snapshot.json
```

输出是包含 reports.usage / reports.analytics 的合集；手动上传网页时，应使用图形界面的“导出 JSON”生成两个独立文件。命令失败时输出 error 字段，进程退出码为 1。程序为 GUI 子系统，PowerShell 自动化可使用 Start-Process -Wait 等待它完成。

## 源码构建

安装 Python 3.12 x64 后，在 source 目录运行 build.ps1。脚本会在源码目录创建隔离构建环境，安装固定版本的 PyInstaller，并将 EXE 输出到上一级目录。程序日常运行不需要构建工具。

v1.0 基础版本的单文件 EXE 已实际执行无窗口采集并取得真实 usage / analytics 数据。v1.2.1 更新版通过可控时钟和本地 HTTP 服务端到端验证定时器、通知与重置历史；EXE 验证窗口、托盘注册与正常退出。地址与上传密钥均未预置进程序或交付包。
