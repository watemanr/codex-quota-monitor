# Codex 额度观察

服务使用 HTTP 8765。下文的 `192.0.2.10` 是文档专用示例地址，部署时请替换为自己的服务器地址。此服务接受采样，保存历史并推断重置；它不会自行访问或修改 OpenAI 账户，也不会自动兑换重置信用。

## 服务位置

- 网页示例：`http://192.0.2.10:8765/`
- 上传：`POST /api/usage`
- 看板：`GET /api/dashboard?account=my-codex&days=7`
- 账号：`GET /api/accounts`
- 健康检查：`GET /healthz`
- OpenAPI：`GET /openapi.json`
- 容器：`codex-quota-monitor`，开机自动启动，1 个 Gunicorn worker / 4 线程，192 MiB 内存上限。
- 源码：`/opt/codex-quota-monitor/app`
- SQLite 持久数据：`/opt/codex-quota-monitor/data/quota.sqlite3`（WAL 模式）
- 密钥及规则：`/etc/codex-quota-monitor.env`（root，0600）

服务器安装按 [Flask 官方 Gunicorn 部署文档](https://flask.palletsprojects.com/en/stable/deploying/gunicorn/) 使用生产服务进程。容器使用非 root 用户、只读根文件系统和独立数据目录。

## 网页登录与改密

首次部署会为本服务器生成独立的 **48 字符随机登录密码**，保存于 `/etc/codex-quota-monitor.env` 的 `WEB_PASSWORD`。源码和镜像不包含通用默认密码。这个密码与 Windows 采集器的 `UPLOAD_TOKEN` 分开，网页改密不会影响自动上传。

登录后点右上角 **修改密码**，输入当前密码、新密码和确认密码。新密码需 12–256 个字符；保存后所有浏览器会退出，使用新密码重新登录。数据库只保存密码哈希；网页修改会持久保存，容器重启后仍然有效。会话有效期为 24 小时。

也可以编辑 `/opt/codex-quota-monitor/app/docker-compose.yml`，取消下列两行的注释，填入你自己的新密码（保持缩进）：

```yaml
    environment:
      WEB_PASSWORD: '这里替换成你自己的长随机密码'
```

然后执行：

```bash
cd /opt/codex-quota-monitor/app
sudo docker compose up -d --force-recreate
```

普通 `restart` 不会重新加载 YAML 环境变量。**只有配置值变成新值**才会覆盖网页保存的密码；未改变的 YAML / env 初始值在重启时不会把网页修改还原。忘记密码时也可用此方法重设。若密码包含 `$`，在 Compose YAML 里写成 `$$` 防止变量替换；建议使用字母、数字、`-`、`_` 的随机字符串。

初始配置也可直接修改 root 权限的 `/etc/codex-quota-monitor.env` 中 `WEB_PASSWORD` 后重新创建容器；如果 YAML 已设置 `WEB_PASSWORD`，以 YAML 为准。高级部署支持 `WEB_PASSWORD_HASH`，但设置 `WEB_PASSWORD` 时优先使用后者。部署脚本升级时保留已部署 YAML 中的自定义配置。

浏览器通过 HttpOnly、SameSite=Lax 会话 Cookie 登录；HTTPS 反代时设置 Secure。登录和修改密码均有限速，修改密码及退出校验请求来源和 CSRF。密码不会保存在 JavaScript 存储中。

## 采集器状态、重置时间轴和额度天气预报

额度总览按账号显示最近一次 Windows / Mac 采集器成功上传时间、最新采样时间以及上传状态。30 分钟内标为最近有上传，超过 30 分钟提示延迟，超过 2 小时提示长时间未上报。它只反映服务器收到的上传，不能证明客户端进程在线；手动上传不会冒充采集器，积压队列的新上传会同时显示旧采样时间。

重置事件时间轴独立读取实际检测到的计划内重置、疑似突发重置和待确认事件，不会被普通变化记录的 200 条上限挤掉。它与最近的 Tibo 额度相关文字帖文按北京时间排列；帖文只提供上下文，不作为重置判定依据。所选范围和账号筛选与总览同步。“重置与变化记录”位于时间轴前，默认显示筛选后的最近 4 条；需要时可展开全部已返回记录，切换账号、范围或类型后重新折叠。

「更多」中的额度天气预报使用同一周期最近连续采样：5h 最多回看 2 小时、weekly 最多回看 48 小时；至少 3 条采样，分别覆盖至少 10 分钟或 2 小时，且已用比例至少增加 1 个百分点。最新采样超过 30 分钟、预计重置时间已过或趋势无法判断时不输出耗尽时间。若按趋势估计耗尽发生在计划重置之后，只显示“计划重置前预计不会用尽”。这是粗略外推，不代表平台承诺。

只读接口：`GET /api/forecast?account=账号`；省略 account 返回全部账号。`/api/overview` 和 `/api/dashboard` 新增 `collectors` 与 `timeline_events` 字段。

## Tibo 的 X 动态

额度总览底部显示 Tibo（[@thsottiaux](https://x.com/thsottiaux)）最近的公开帖文文字。服务器每 10 分钟读取一次 [Nitter 公开 RSS](https://x.noodl3.net/thsottiaux/rss)，只处理标题文字、发布时间和原帖 ID；不下载图片，也不直接抓取 X 页面。最多显示最近 20 条，SQLite 保留最近 80 条去重缓存；读取失败时保留上次成功内容，并显示缓存时间与更新失败提示。网页读取的是本地缓存，不依赖浏览器加载 X 嵌入，也不需要 X API 密钥。RSS 是第三方镜像，可能延迟或遗漏；点击每条原帖链接核对。动态不是重置判定依据，服务仍只按实际额度采样生成事件。

## Bark 推送

网页登录后打开「Bark 推送」页面，为每个 Codex 账号分别设置 Bark **服务器地址**和**设备 key**。地址只填服务器根地址，例如 http://服务器地址:40011，不要填 key、/push、标题或消息正文。保存后网页只显示 key 的末四位，原 key 不会通过读取接口返回；需要发通知，因此 key 保存在服务器的 SQLite 数据库中，数据库备份也包含它。

服务端按 [Bark 的 POST /push 接口](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)发送 JSON，请求体包含设备 key，避免 key 出现在请求 URL 和访问日志中。通知分组默认是 Codex额度。设置页的「发送测试通知」需要手动点击，保存配置本身不会发测试消息。

每个账号可以单独开启或关闭：

- 5h / weekly 额度重置：只在新采样显示已用量明显下降、被判定为计划内或疑似突发重置时通知。预计重置时间移动、没有额度回升的周期切换不作为重置提醒。
- 5h / weekly 低额度：剩余比例首次从阈值以上降至阈值及以下时提醒；初始新采样已低于阈值时也会提醒一次，持续低额度不会每次采样重复推送；为避免数值抖动，需回升超过阈值约 2 个百分点后才重新准备提醒。默认阈值 5%。
- 定时剩余额度报告：间隔 0 表示关闭，其他值为 5–10080 分钟。报告注明每个额度窗口的最后采样时间；没有新采样时仍会注明旧数据时间，不会伪装成实时数值。
- Tibo 额度相关新帖：按公开文字中的额度关键词匹配，发送原文摘要、北京时间和原帖链接。这是帖子提示，不代表已发生重置。首次开启最多补推近 6 小时内最新的一条相关帖；后续仅推送新发现且发布时间在 24 小时内的帖文。同一 Bark 地址与设备 key 去重，避免多账号重复通知。

消息先写入 SQLite 队列，再由服务端后台任务发送。短暂网络故障会退避重试，最多尝试 5 次；设置页可查看最近发送状态。账号改名会迁移 Bark 设置，合并两个都已有 Bark 配置的账号会被拒绝以避免覆盖，删除账号会删除对应设置和未发送消息。部署后默认为未配置、未启用；此前的历史重置事件不会补发通知。Tibo 帖文通知须单独勾选，也受账号自动推送总开关控制。

## Nginx

复制 `nginx.conf.example` 中的 location 到你自己的 server 块。同机 Nginx 转发 `http://127.0.0.1:8765`，其他机器上的 Nginx 可参考 `http://192.0.2.10:8765`，并将示例 IP 替换为自己的服务器地址。若 Nginx 本身在容器内，127.0.0.1 指该 Nginx 容器，请使用可达的宿主机地址。

支持 `/quota/` 一类子路径：location 和 proxy_pass 都保留末尾 `/`。前端接口和静态资源使用相对路径。服务本身只监听 HTTP；外网域名的 HTTPS 由你的 Nginx 处理。服务未修改服务器已有的反向代理配置。

## 上传真实额度

请求头：

```http
Authorization: Bearer <UPLOAD_TOKEN>
Content-Type: application/json
```

推荐将 `get_usage_limits` 的原始返回放入 `usage`：

```json
{
  "account": "my-codex",
  "observed_at": "2026-09-22T15:00:00+08:00",
  "source": "codex-desktop",
  "report_id": "为本次采样生成唯一ID",
  "usage": {
    "rateLimitsByLimitId": {
      "codex": {
        "primary": {"usedPercent": 25, "windowDurationMins": 300, "resetsAt": 1790071200},
        "secondary": {"usedPercent": 45, "windowDurationMins": 10080, "resetsAt": 1790676000}
      }
    }
  }
}
```

以上百分比和时间仅是格式示例，不能当作真实额度上传。支持 `rateLimits` 旧格式、`rateLimitsByLimitId` 新格式及完整 MCP text content 外层。存在非空新格式时优先采用，避免同一额度被重复记录。`primary` 不一定是 5 小时：以 300 / 10080 分钟判别。空窗口不补零。

也可上传标准格式：

```json
{
  "account": "my-codex",
  "observed_at": "2026-09-22T15:00:00+08:00",
  "report_id": "另一个唯一ID",
  "windows": [
    {"id": "codex:300", "window_minutes": 300, "used_percent": 25, "resets_at": 1790071200},
    {"id": "codex:10080", "window_minutes": 10080, "used_percent": 45, "resets_at": 1790676000}
  ]
}
```

标准格式可用 `remaining_percent` 替代 `used_percent`。同时提供时两者必须相加等于 100。`resets_at` 可为 null，未知不伪造。时间支持 Unix 秒、Unix 毫秒或含时区的 ISO 8601；拒绝无时区时间和超过服务端 5 分钟的未来采样。

`account` 必须长期固定，建议使用 `my-codex`。同一采样重试要保持 `report_id`、`observed_at` 和内容不变；成功重复返回 `200 duplicate`，冲突返回 `409`。如果不传采样时间，按接收时间建立记录，因此推荐始终传真实采样时间。旧采样保存但返回 `out_of_order`，不回改既有基线或事件。

```bash
curl -f http://127.0.0.1:8765/api/usage \
  -H "Authorization: Bearer $UPLOAD_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @sample.json
```

GET 数据接口支持访问密钥 `READ_TOKEN` 和上传密钥 `UPLOAD_TOKEN`；上传接口只接受后者。浏览器使用独立的网页登录密码；API 客户端继续使用 Bearer 密钥。手动上传密钥不保存。

## 让 GPT 使用

上传指令模板：

> 读取当前 Codex 的额度，不进行额度兑换。记录真实采样时间，将完整的 get_usage_limits 返回值放入 usage，account 固定为 my-codex，每次采样生成 report_id。使用配置的上传密钥以 Bearer 方式 POST 到我的额度服务 /api/usage。重试保持原始采样时间、ID 和内容不变。只上传实际返回的窗口，缺失窗口不要自行补全。

有 HTTP 调用能力的代理可直接调用。配置 GPT Action 时，使用 `openapi.json`，将 `servers[0].url` 改为最终 HTTPS 域名（有子路径时包含该子路径），并在 Action 的身份验证中填写上传密钥。是否能读取 Codex 额度，取决于那个 GPT/代理是否具有相应的账户读取工具；该网页不会凭空赋予读取能力。

此次仅部署接收服务，没有创建定时采集任务。为了降低漏检，可由采集端每 5–10 分钟上报；若重置后额度在两次采样之间重新消耗且预计重置时间也没变，仅靠这两条数据无法识别。

## 判断规则

1. 首条：建立基线，不判断发生过重置。
2. 已用额度下降至少 2 个百分点，且采样区间跨过上一条有效的预计重置时间：计划内重置（符合时序，不证明平台内部原因）。
3. 下降达到阈值，两次采样都早于原计划 5 分钟以上：疑似突然重置。若同时预计重置时间延后，证据更强；仍可能是人工兑换或额度校正。
4. 原计划到期后重置时间后移到下一周期、但未观察到额度明显回升：计划周期切换。
5. 只有预计时间改变：重置时间变化，不当作已确认重置。
6. 缺少有效重置时间、原重置时间已经过期、变化处于边界、或采样间隔跨过一个以上周期：待确认。
7. 小于 2 点的下降：小幅校正；只消耗额度不会新增变化事件。

事件时间是检测到变化的采样时间；真实变化发生于页面标出的前后采样区间。倒计时到期不会擅自恢复额度。超过 30 分钟无新采样会明确提示过期。5 小时与每周分别判断，不会强行关联；各账号、各额度桶相互隔离。

规则可通过环境文件调整：`RESET_TOLERANCE_SECONDS=300`、`MINIMUM_DROP_PP=2`。修改后重新运行部署脚本使环境生效。页面每 30 秒刷新展示，这不等于自动采集。


## 多账号总览（v1.1）

首页默认选择“全部账号”，同时显示每个账号的 5 小时和每周额度、预计重置时间与采样状态。缺失窗口单独显示“未上报”。点击该账号的“查看历史”可进入单账号走势；选择器可切回“全部账号”。变化记录会标出所属账号，每个账号独立判断重置，不会混合额度。

每个账号上传到相同的 POST /api/usage，使用现有 UPLOAD_TOKEN，只需要给 JSON 顶层设置不同且固定的 account 名称，例如 personal、work、backup。无需事先注册账号。新账号首条数据到达后，首页下次自动刷新即会显示。不要用同一个 account 名称上传不同 OpenAI 账号的数据。

GET /api/overview?days=7 返回全部账号的最新额度和变化记录。访问密钥具有查看全部账号的权限，上传密钥可上报任何账号；适用于统一管理自己的多个账号。

多账号版本验收：32 项后端测试通过；浏览器验证了三个账号同时展示、单账号历史切换、新账号出现、桌面/手机布局、缺失窗口与账号名称转义。模拟账号只存在于测试浏览器，正式数据库未添加演示账号。


## 用量分析（v1.2）

点击顶部“分析”查看 7/30 天堆叠柱状图、功能占比、聊天用量排行和套餐周期历史。分析按账号查看，避免把不同账号的额度百分比相加。总览仍支持同时显示所有账号。

- 日图支持按功能、模型、客户端和触发方式分组；日期按 UTC，与源统计一致。鼠标悬停或键盘聚焦某一天，可查看当天的构成。
- 图例百分比表示当前选择的总用量构成，不表示剩余额度。源单位 percent 的日数据展示为相对用量，不用于反推 Token 或美元。
- 聊天排行与原应用采用相同含义：最近 30 天活跃本机根聊天的累计消耗，含本机已知子任务，对比当前套餐完整额度。它不受日图的 7/30 天筛选影响；累计占比可能超过 100%。
- 源未提供的明细显示“—”，不会被补成零。真实零额度消耗显示 0。
- 套餐历史将 basis points 除以 100 转为百分比。例如 5577.5 basis points = 55.775%。保留数据截至时间、约计和覆盖不完整标记；不是实时额度。
- 检测到计划内或疑似突发重置时，按该账号、该额度窗口将旧周期截断，新周期从重置边界开始。计划内重置采用原计划时间；突发重置采用首次检测时间，页面同时显示前后采样区间。若上游仍只给旧周期汇总，新周期百分比显示“—”，不把旧用量分摊过去；新周期的预计结束时间取重置后上报的新时间。此前保存的源统计快照用于保留旧周期数据。原始上报及事件不被改写。

### 采集和上传

在已经登录相应 Codex 账号的电脑上运行：

```bash
python collect_analytics.py --account my-codex --output analytics.json
```

有多个独立登录目录时，可加 --codex-home 指定目录，并为每个账号指定其在网页中的固定 account 名称。脚本读取本机 Codex 登录状态，只将凭证发送到 chatgpt.com；输出 JSON 只包含用量、聊天 ID、标题和子任务数量，不包含登录凭证或聊天正文。Oracle 服务器不保存 OpenAI 登录凭证。

脚本基于本机 Codex Desktop 26.915.4065.0 的实际统计请求实现，涉及内部接口，未来应用更新时可能需要适配。基础账户 Token 统计的公开协议可见 [OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server#7-token-usage-chatgpt)，它与本页完整分析字段不是同一个接口契约。

将生成的 JSON 上传：

```bash
curl -f http://你的服务地址:8765/api/analytics \
  -H "Authorization: Bearer $UPLOAD_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @analytics.json
```

也可以打开网页“接入 / 上传”，粘贴该 JSON 和现有上传密钥，页面会自动选择 /api/analytics。所有账号共用现有密钥。分析明细与额度快照是两个独立接口；原 /api/usage 上传方式继续有效。

没有建立新的定时任务。本次导入了一份真实分析数据；后续需要重新运行采集脚本并上传，才能持续更新。源数据可能延迟，页面会区分采集时间和源统计时间。

### 持久化和边界

分析快照写入原 SQLite 文件的 analytics_state / analytics_reports 表。新快照按日期合并最近 366 天日数据，最多保留 500 个套餐周期；聊天列表使用最新完整快照。旧采样不覆盖新采样，同一 report_id 重试幂等。部分查询失败时只上传成功的区块，保留已有的其他区块。若源统计时间倒退，保留较新的那个区块。

单次请求仍限制 256 KiB。当前实际分析包约 157 KiB。采集器最多查询 100 个近期本机根聊天；子任务超过接口上限时跳过并标记截断。其他电脑的独有本地任务不在该电脑的排行范围内。

## 最近重置记录（2026-09-22 更新）

每个账号的 5h / weekly 卡片分别显示最近一次检测到的计划内重置、计划周期切换或疑似突发重置。记录从完整事件历史获取，不受图表日期筛选影响；没有确切记录则显示“尚未检测到重置”。缺少证据的变化仍保留为待确认，不填入已确认的最近重置记录。

GET /api/reset-status?account=账号 支持访问密钥或上传密钥，返回按 window_id 索引的 last_resets。每条包含 detected_at、interval_start、expected_reset、window_type、kind、type_label 等。检测时间是首次采样发现变化的时间，不是精确发生时间。

Windows v1.2.0 在本机执行相同检测，并在每轮上传后同步网页历史；同步旧历史不重复通知。数据库沿用原有采样与事件，更新只新增查询索引，不删除历史数据或更换密钥。

## 账号管理

登录网页后点击「账号管理」进入独立管理页（/static/manage.html），可以改名、合并两个账号的数据、删除账号及全部历史；删除前须输入完整账号名。入口是普通链接，即使看板脚本被代理缓存也能打开管理页。网页会话与 CSRF 校验保护这些写入操作，上传密钥和只读密钥不能执行账号管理。

改名和合并会在同一数据库事务中迁移额度上报、采样、重置事件、分析上报及源统计快照；旧名称保存为别名，原采集器尚未更改账号名时，后续上传及重置状态查询仍自动归入保留账号。账号可以直接改回属于自己的旧名称。管理页也可单独解除旧名称占用：原有历史保留在当前账号，随后用旧名称上传会产生独立账号。已删除名称会拒绝继续上传，管理页可单独解除封锁以重新使用该名称。

合并时，相同日期的分析统计采用较新的快照，不把百分比相加；同一套餐周期也只保留较新的统计。若两账号具有相同上报 ID 或同一额度窗口在同一时刻存在两条采样，合并返回 409，双方数据保持不变，避免覆盖或伪造数据。合并保留已经生成的重置判断，不重新推断历史事件。
